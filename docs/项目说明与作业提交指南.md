# 炼化实验室：项目说明与作业提交指南

## 1. 文档用途

这份文档把工作区根目录《作业要求.txt》整理成项目说明，说明本项目完成了什么、为什么这样组织、怎样运行和怎样提交。它同时供三类人使用：

1. 老师或评审：快速核对作业要求与项目完成情况；
2. 提交者：按清单准备网页链接、案例压缩包、视频、说明文档和结课报告；
3. 后续开发者：了解代码入口、案例契约和可继续修改的位置。

作业原文仍保存在项目上一级目录的 `作业要求.txt`，本文件不是对原要求的替换，而是结合实际项目的执行说明。

## 2. 作业要求整理

### 2.1 课程作业目标

作业要求围绕“学科交叉”和“可视化”构造智能化石油应用场景。案例需要同时说明：

- 石油相关业务在做什么；
- 传统做法或实际判断中有什么问题；
- 机器学习、深度学习或其他智能方法介入哪一步；
- 数据和计算结果如何通过可视化让读者看懂。

可视化是本作业的核心表现形式。它不是给页面加几张装饰图，而是要帮助读者理解工艺、流程、数据关系和模型结果。

### 2.2 按学号确定必做类别

石油勘探开发过程按网站中的 13 个阶段分类。学号按最后两位循环对应类别：学号 1 对应第 1 类，学号 13 对应第 13 类，学号 14 再回到第 1 类。

本项目学号为 **13**，对应：

| 项目 | 内容 |
| --- | --- |
| 必做类别 | 第 13 类：加工 |
| 必做场景数 | 加工类别下的全部子类别，共 5 个 |
| 完成案例 | r1、r2、r3、r4、r5 |
| 是否需要补充其他类别 | 不需要。加工类别已经达到并超过至少 5 个案例的要求 |

### 2.3 每个案例必须满足的内容要求

每个案例都应当是一个独立的石油业务问题，并包含三个内容分区：

1. **专业背景**：用直白的语言解释工艺、业务对象、输入数据和问题边界，并尽量用示意图、结构图、数据表等方式强化概念；
2. **案例流程**：拆解从数据准备到模型计算、结果评价和人工判断的步骤，说明每一步做什么、输出什么、哪里容易出错，并用流程图或步骤图辅助说明；
3. **案例演示**：做一个纯前端的代表性演示，用参数控件、图表、指标卡、筛选器或结果表展示数据分析和计算结果。

案例不要求做成生产系统，但必须能看出石油背景、智能方法和可视化之间的关系。教学演示中的模型可以简化，不能只显示固定数字或只放静态图片。

### 2.4 主网站兼容要求

主网站提供“添加案例”入口。新制作的案例必须保持原案例包格式，能够在主网站中直接选择或拖入整个文件夹后完成校验、预览和添加，不应要求修改主网站代码才能使用。

本项目重构了页面外壳和导航，但保留了原案例导入契约：

```text
案例文件夹/
├─ case.json          必需：元信息、专业背景、案例流程
└─ demo/              可选但本项目五个案例均提供
   ├─ index.html      整页演示入口
   ├─ demo.css        演示样式
   ├─ engine.js       共用数值与图表函数
   └─ demo.js         当前案例的模型与交互
```

导入器支持完整文件夹、多文件选择、整页模式和模块模式；案例资源会被打包为可离线运行的内容。导入后的案例保存在当前浏览器中，内置案例则随网站源码一起提供。

### 2.5 纯前端要求

项目不使用后端代码、数据库或 CDN。页面由 HTML、CSS 和 JavaScript 组成，模型计算在浏览器中完成，案例包可以直接打开或通过静态网页服务器运行。

### 2.6 作业提交内容

原作业要求包括以下内容：

1. 一个网站发布链接；
2. 每个案例一个压缩文件，压缩包名称使用“大类别-小类别”，不能把多个案例放到同一个案例压缩包里；
3. 一个展示网站关键亮点的视频，原则上不超过 5 分钟，并且需要讲解；
4. 一个说明文档，说明案例数量、案例内容、关键亮点和做得好的部分及原因；
5. 一个 PDF 格式的结课报告。首页包括项目名称、学号、姓名等，正文至少包括对可视化的理解、使用的可视化技术及效果、课程建议；正文不少于 3 页，不含首页。

本次代码工作完成的是网页源码、五个独立案例包和说明文档。视频、网站发布和 PDF 结课报告需要在提交阶段另外准备，不能把本地 `workspace` 路径当作最终网站链接。

## 3. 项目定位和设计思路

### 3.1 项目名称

**炼化实验室：石油加工交互案例**

英文辅助标识：`REFINERY LAB / PROCESSING`

### 3.2 一句话定位

把加工环节里的五个具体问题拆成“工艺背景—计算流程—交互演示”，让读者能直接看到参数、模型和结果之间的关系。

### 3.3 页面结构

| 页面 | 作用 |
| --- | --- |
| 首页 | 展示加工类别、五个案例入口、整体流程位置和项目说明 |
| 全部案例 | 按关键词、环节、AI 方法和难度筛选案例；可切换查看尚未接入的候选场景 |
| 环节分类 | 展示某个石油流程环节下的场景列表，并标出已有案例和待接入场景 |
| 方法索引 | 从 AI 方法反查可应用场景，方便从技术角度寻找问题 |
| 场景详情 | 在专业背景、案例流程和交互演示三个 tab 之间切换 |
| 接入指南 | 说明案例包结构、字段、导入步骤和检查规则 |

页面外壳使用流程编号、颜色标识、案例侧栏、面包屑和“下一个案例”导航组织内容。移动端提供折叠导航，案例演示保持自己的沙箱和样式边界。

### 3.4 文案原则

标题、问题和说明都直接说清楚要判断什么。例如：

- “收率想高一点，能耗和产品质量还能满足要求吗？”
- “单项还没超限，多个测点是否已经一起偏离正常？”
- “每个数字都在允许范围，组合起来是否仍然可疑？”

这些问题比“探索智能化未来”“赋能产业升级”等空泛表述更适合带着读者进入案例。

## 4. 五个案例说明

五个案例都属于第 13 类“加工”，对应网站中的 r1—r5 场景。每个案例有 4 段专业背景、5 个流程步骤和一个可运行的整页演示。

### 4.1 r1：常减压装置操作优化

- **业务问题**：调整炉温、回流比和压力后，轻馏分收率会变化，但能耗和柴油闪点也会受到影响。
- **智能方法**：用二次岭回归估计多个响应，再在约束条件下搜索较合适的操作参数。
- **演示内容**：拖动工况参数，观察收率、能耗和闪点；查看可行解、约束状态和预测结果。
- **可视化重点**：分馏塔示意图、参数—响应关系图、约束对比和寻优结果。

### 4.2 r2：催化裂化产物预测

- **业务问题**：反应温度、剂油比和停留时间变化后，汽油、液化气等多个产物收率会一起变化。
- **智能方法**：使用距离加权 k 近邻回归，按训练集中相似的工况预测六类产物收率。
- **演示内容**：调节反应条件，查看六类产物预测、相似样本、测试误差和收率变化。
- **可视化重点**：工况散点关系、六类产物条形图、相似样本距离和误差指标。

### 4.3 r3：炼化设备预测性维护

- **业务问题**：单个振动或温度测点还没有超过阈值时，多个测点的组合可能已经偏离正常状态。
- **智能方法**：用多变量高斯分布描述正常设备状态，计算联合异常分数并连续观察趋势。
- **演示内容**：播放或拖动设备退化过程，比较联合异常检测和单一振动阈值的报警时间。
- **可视化重点**：多测点时间序列、联合异常分数、阈值线、报警时间和特征偏离量。

### 4.4 r4：化验数据智能审核

- **业务问题**：密度、闪点和硫含量单独看都可能在范围内，但组合起来仍然可能是异常记录。
- **智能方法**：把教学范围规则与孤立森林结果合并，筛出进入人工复核的样本。
- **演示内容**：调整异常分数阈值、启用或停用范围规则、只看待复核样本、改变排序、点击散点或表格行查看判断依据，并支持 CSV 导入和导出。
- **可视化重点**：密度—闪点散点图、异常分数阈值、审核指标卡、逐条决策说明和规则/模型对比图。

### 4.5 r5：产品质量在线软测量

- **业务问题**：实验室化验结果存在时间滞后，过程变量已经变化时，现场需要估计当前产品质量。
- **智能方法**：用岭回归从连续过程变量估计重整汽油辛烷值，并用残差区间表达估计的不确定性。
- **演示内容**：播放过程时间线，观察软测量值、滞后化验值、区间和误差变化。
- **可视化重点**：过程变量时间序列、预测区间、化验值与估计值对照、误差和播放控制。

## 6. 案例包和导入规则

### 6.1 文件命名

案例文件夹已经按“大类别-小类别”命名：

```text
加工-常减压装置操作优化
加工-催化裂化产物预测
加工-炼化设备预测性维护
加工-化验数据智能审核
加工-产品质量在线软测量
```

提交案例压缩包时，一个文件夹单独压缩，不能把五个案例合并为一个案例压缩包。

### 6.2 清单字段

`case.json` 至少需要这些内容：

- `id`：全局唯一的小写连字符 ID；
- `sceneId`：网站中已有的场景 ID；
- `title`：案例标题；
- `methods`：使用的 AI 方法标签；
- `presentation`：算法、难度、问题、摘要和数据说明；
- `tabs.background`：专业背景、判断信息和分段内容；
- `tabs.workflow`：案例流程、步骤、输出和失败模式；
- `tabs.demo`：演示入口或示范页配置。

### 6.3 导入步骤

1. 打开网站，点击右上角“添加案例”；
2. 选择或拖入完整案例文件夹；
3. 检查清单、场景、背景、流程和演示资源的校验结果；
4. 点击“试跑示范”确认交互页面可用；
5. 校验全部通过后点击“校验并添加”；
6. 进入对应场景页，检查三个 tab、标题、算法信息和演示结果。

导入案例保存在当前浏览器的 `localStorage` 中，换电脑或换浏览器时需要重新导入。网站内置的五个案例已经打包进 `assets/cases.bundle.js`，不依赖本地导入记录。

### 6.4 资源和运行边界

- 单个导入包上限为 6 MB；
- 图片、SVG、JSON 等案例资源可放在案例文件夹内；
- 整页模式使用 `demo/index.html`，脚本和样式在沙箱 iframe 中运行；
- 案例中的定时器、播放和窗口事件需要在离开页面时清理；
- 教学范围、阈值和合成数据不等同于工业标准，不应直接用于生产操作。

## 7. 运行、构建和验证

### 7.1 直接运行

无需安装第三方依赖，双击 `index.html` 可以打开。开发时更建议从 `workspace` 的上一级目录启动静态服务器：

```powershell
cd D:\MyWorkSpace\visualization\work5
python -m http.server 5173 --bind 127.0.0.1
```

浏览器访问：

```text
http://127.0.0.1:5173/workspace/
```

### 7.2 修改后构建

```powershell
cd D:\MyWorkSpace\visualization\work5\workspace
npm run build
```

构建脚本会重新读取五个案例，打包到 `assets/cases.bundle.js`，同时更新 `index.html` 的内容版本参数，避免浏览器继续使用旧缓存。

### 7.3 检查命令

```powershell
npm run check
```

检查内容包括：

- 岭回归、k 近邻、异常检测、软测量等数值函数；
- 训练集、校准集和测试集的用途分离；
- CSV 导入的列名、数值格式、行数和异常输入；
- 五个案例包是否有正确的清单、背景、流程和演示；
- 原网站格式案例是否能被当前导入器识别；
- 导入后流程图和算法展示字段是否保留。

当前结果：`npm run check` 通过 119 项。

页面检查另外覆盖真实 DOM 路由、案例库筛选、筛选条件恢复、案例 tab 切换、流程步骤保持、空状态和非加工场景导航，共通过 48 项。

## 8. 后续接手说明

后续开发从 `workspace` 目录开始，不要直接改生成后的 `assets/cases.bundle.js`。建议顺序如下：

1. 修改单个案例：编辑对应 `cases/加工-.../case.json` 和 `demo/demo.js`；
2. 修改通用算法或图表：编辑 `tools/engine.js`；
3. 修改通用演示样式：编辑 `tools/demo.css`；
4. 修改页面结构和路由：编辑 `assets/app.js`、`assets/styles/main.css` 或 `assets/styles/refinements.css`；
5. 执行 `npm run build`，再执行 `npm run check`；
6. 用浏览器打开 `workspace/index.html`，检查案例导入和移动端页面。

几个需要保持的约束：

- `sceneId` 必须来自主数据中的已有场景；
- 案例 ID 必须全局唯一；
- 五个案例仍应保持“专业背景—案例流程—交互演示”的三段结构；
- 新增案例不能破坏原网站的 `case.json + demo/` 导入方式；
- 不要把生成文件和测试临时文件写进案例目录；
- 演示数据和模型结果要在页面中明确标为教学合成数据或示范性结果。
