## 专家视角的不足与风险

### 高优先级（提交前必须补齐）

1. **提交物仍不完整。**仓库没有网站发布链接、五个独立压缩包、带讲解且不超过 5 分钟的视频、最终说明文档和 PDF 结课报告。姓名、学号确认和最终链接必须由提交者提供，不能由代码推断。
2. **真实浏览器验收尚未由仓库 CI 证明。**当前仓库没有原有 GitHub Actions；新增检查只验证构建、数值和案例契约。提交前仍需在目标浏览器检查首页、五个案例、导入流程、移动布局和下载文件。
3. **模型有效性边界需要在答辩中主动说明。**五个案例使用固定随机种子和合成响应，训练/测试分离是教学演示，不等同于真实装置的时间外推、跨原油切换验证或上线模型。不要把指标当成工业精度、产品标准或操作规程。

### 中优先级（建议优化）

4. **数据出处与可复现性。**案例说明已列参考链接和随机种子，但没有真实数据集、单位校准或版本化实验记录。后续可为每案补一页“数据生成假设、单位、随机种子、适用范围”。
5. **工艺语境。**背景和流程是正确的入门级简化；复杂的滞后、传感器校准、设备联锁、工艺安全和跨产品约束未建模。应继续使用“概念示意/教学设置”标签，避免添加看似真实但无来源的阈值。
6. **可访问性与降级体验。**主站已有跳过链接、语义导航和部分图表 aria-label；仍需用键盘逐页走完导入弹窗、案例 tab、筛选器、CSV 导入和 iframe 演示，并检查无脚本、窄屏、高对比度和减少动画模式。
7. **性能与浏览器兼容。**案例包和 assets/cases.bundle.js 体积较大；需在目标浏览器检查首次加载、切换五个案例后的内存和定时器清理。不要仅凭桌面开发者工具结论宣称手机性能。

### 低优先级（可选）

8. 统一案例中的术语、单位和图表配色，并在演示中提供“恢复默认值”与“当前输入范围”提示。
9. 将提交检查结果写入带日期的报告；若模型或案例更新，必须重新生成 bundle 后再检查。

## 提交前验收顺序

1. 在目标浏览器运行 npm run build && npm run check。
2. 打开首页、加工分类和五个案例，逐项切换三个 tab、控件、图表、空状态和移动布局。
3. 用一个独立案例文件夹走完添加、校验、预览、导入和刷新恢复；确认单包不超过 6 MB。
4. 分别压缩五个案例，核对每个压缩包根目录含 case.json。
5. 录制 ≤5 分钟讲解视频，生成说明文档和 ≥3 页正文的 PDF；确认全部来自同一提交版本。
6. 仅在提交者确认发布地址、姓名和学号后填写最终提交信息。

## 明确不能从源码推出的事项

- 课程平台截止日期、姓名/学号是否最终正确、正式网站 URL；
- 真实装置数据许可、工业阈值、模型上线资格；
- 真实手机/浏览器兼容性；
- PDF 和讲解视频是否已提交。
